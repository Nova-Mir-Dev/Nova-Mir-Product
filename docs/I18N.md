# Internationalization Guide

How translations are written, verified, and shipped in this repo.

## Current state

| Locale | Status            | Register      | Reviewed by a native speaker? |
| ------ | ----------------- | ------------- | ----------------------------- |
| en     | Source of truth   | —             | yes (brand copy)              |
| es     | **Machine draft** | tú (informal) | **no — pending**              |
| ru     | **Machine draft** | вы (formal)   | **no — pending**              |

The es and ru catalogs were drafted by an AI agent informed by the register
research below. They are structurally correct and conventionally plausible,
but **no machine draft ships to production marketing surfaces without a
native-speaker review pass**. Review beads track this.

## The pipeline

1. Strings live in `messages/{locale}.json`, one file per locale.
2. `i18n/locales.ts` is the single source for the locale list; adding a locale
   means adding it there plus a catalog file plus the `messageMap` entry in
   `i18n/request.ts`.
3. Locale is resolved per-request in `i18n/request.ts`: `locale` cookie first
   (set by the dashboard's LocaleSwitcher via a server action), then the
   `Accept-Language` header, then `en`.
4. Automated verification (`src/features/i18n/__tests__/catalog-parity.test.ts`)
   is **structural only**: every locale must expose the same key paths as en,
   no empty strings, and identical ICU `{placeholder}` sets per string. It
   cannot judge linguistic quality — that is what the human review pass is for.

## Register decisions

Decided 2026-07-18 against the brand voice
(`Nova Mir Planning/tasks/business-knowledge/brand-voice.md`) and observed
market convention.

### Spanish: tú

The brand voice is collaborative and personal ("write like a person, not a
marketing department"; "Tell us about your project", not "Submit your
requirements"). In Spanish-language software for small-business owners, that
voice maps to tú — Shopify's Spanish site (the closest audience analog) uses
tú throughout ("Personaliza tu tienda"). Usted would read as the
corporate-agency register the brand explicitly positions against. Neutral
Latin-American Spanish (es-419), not es-ES: no vosotros.

### Russian: вы (lowercase)

Russian expresses warmth within вы; ты is for youth brands and games. Tilda —
a Russian website builder, the nearest market analog — is warm and direct
while being 100% вы ("Вам не обязательно быть дизайнером"). System messages
("delete your account?") read wrong in ты. Use modern lowercase вы, not the
old-fashioned capitalized Вы. Never mix registers within a locale.

## Conventions and open review points

Vocabulary was drawn from convention-setting products (Shopify es, Tilda ru,
VK, Microsoft locale style guides). Flagged choices for native reviewers:

- **ru `Nav.pricing` = "Цены"** — Tilda uses "Тарифы", but that implies
  subscription plans; Nova Mir sells fixed-price projects. Reviewer call.
- **ru `Dashboard.nav.billing` = "Оплата"** — alternatives: "Счета"
  (invoices), "Платежи". The tab shows invoices + payment.
- **ru `Dashboard.nav.privacy` = "Приватность"** — chosen over the full
  "Конфиденциальность" because the mobile bottom-bar tab labels can't fit 18
  characters; "Приватность" is the established software short form (VK).
- **ru `Pricing.ctaButton` = "Обсудить проект"** — deliberately not "Начать
  проект": brand voice avoids transactional get-started CTAs in favor of
  "let's talk".
- **es catalog** — consistently tú already; review for es-419 neutrality and
  brand warmth.

## Adding a locale (checklist)

1. Add the code to `locales` in `i18n/locales.ts`.
2. Create `messages/{code}.json` — copy en.json's structure; machine-draft
   values are acceptable as scaffolding **only if** the review bead is filed
   in the same change.
3. Register it in `messageMap` in `i18n/request.ts`.
4. Add the endonym under `Dashboard.language` in **every** catalog (language
   names always display in their own language: English, Español, Русский).
5. Run the catalog-parity test; file a native-review bead.
6. Check layout: long labels (German, Russian) can overflow the dashboard
   bottom-bar tabs and sidebar; prefer established short forms.

## Pluralization warning (Russian)

No current string uses ICU plurals. When one does, remember Russian has four
CLDR plural categories (one/few/many/other) vs. English's two. A pluralized
ru string must supply all forms:

```
{count, plural, one {# проект} few {# проекта} many {# проектов} other {# проекта}}
```

next-intl handles this natively; the burden is on the string author. Add
plural-form completeness to the parity test when the first plural lands.
